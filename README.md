# kook派单系统

> 版本 v0.1 · 基于 KOOK 官方机器人 API 的游戏社群派单系统 · 零依赖（只需要 Node.js）

在 KOOK 服务器里，**老板**私信机器人下单，**打手**收到卡片一键接单，老板选人后机器人自动发语音频道邀请；打手完成后提交结单，老板用五星评分结单。所有订单和成员角色都可以在一个**只在本机打开**的管理网页上查看和管理。

```
老板私信机器人 / 在频道 @机器人 下单
        │  识别订单（固定格式，或大模型）
        ▼
机器人私信所有「打手」一张卡片 ──→ 打手点 [接单]
        │
        ▼
老板收到报名卡片 ──→ 老板点 [选TA]
        │  生成老板所在语音频道的邀请，连同「开始时间」和 [提交结单] 发给打手
        ▼
打手完成后点 [提交结单] ──→ 老板收到结单卡片：★ ~ ★★★★★ / 暂不结单
        │
        ▼
订单完成：记录结束时间、评分、持续时长，网页上可查
```

## 环境要求

- **Node.js 22.5 或更高**（推荐最新 LTS）。到 <https://nodejs.org> 下载安装即可，**不需要** `npm install`，本项目没有第三方依赖。
- Windows / macOS / Linux 均可。
- 一个你有管理权限的 KOOK 服务器。

检查 Node 版本：在终端里运行 `node --version`，显示 `v22.5.0` 或更高即可。

---

## 第一步：创建 KOOK 机器人

1. 打开 KOOK 开发者后台 <https://developer.kookapp.cn/app/index> 并登录。
2. 点「新建应用」，起个名字（这就是机器人的名字）。
3. 进入应用 → 左侧「机器人」页：
   - **连接模式选 WebSocket**（本项目通过 WebSocket 实时接收消息，不需要公网服务器）。
   - 复制 **Token**。
4. 在本项目**根目录**新建文件 `kook-token.txt`，把 Token 粘进去保存，**只放这一行**。

> ⚠️ Token 等于机器人的全部权限。不要发给任何人、不要截图、不要提交到 Git（`.gitignore` 已经排除了这个文件）。泄露了就去开发者后台重置。

---

## 第二步：把机器人拉进服务器并设置权限

1. 还是在开发者后台的「机器人」页，找到「邀请链接」，勾选权限后复制链接。
2. **用浏览器打开**这个链接（不是在 KOOK 客户端里），选择你的服务器，确认邀请。
3. 回到 KOOK 客户端，服务器成员列表里出现机器人就成功了。

### 机器人需要的权限（最小够用原则）

| 权限 | 用途 | 必需？ |
|---|---|---|
| 查看文字、语音频道 | 收消息、查老板在哪个语音频道 | ✅ |
| 发布消息 | 在频道里回复下单的人 | ✅ |
| 创建服务器邀请 | 给打手生成语音频道邀请链接 | ✅ |
| 管理角色权限 | 在管理网页上给成员加 / 撤角色 | 用网页管角色时需要 |

**不要给机器人「管理员」权限。** 本项目用不到踢人、封禁、删频道等能力；权限越小，Token 万一泄露损失越小。

### 角色排序（重要）

KOOK 规定：**机器人只能授予 / 撤销排在它自己角色下面的角色。** 所以在「服务器设置 → 角色权限」里：

```
管理员            ← 机器人管不了（也不应该管）
机器人自己的角色   ← 放在这里
老板
打手
……
```

如果在网页上给人加角色时提示 `40300 You do not have permission`，基本就是机器人角色排得太低。

---

## 第三步：创建「老板」「打手」角色

在 KOOK「服务器设置 → 角色权限」里新建两个角色，权限和普通成员一样即可：

| 角色名 | 作用 |
|---|---|
| **老板** | 有这个角色的人才能下单；只有下单的老板本人能选人、结单、评分 |
| **打手** | 有这个角色的人才会收到订单推送、才能接单；只有被选中的打手能提交结单 |

然后把对应的人分到这两个角色里（也可以等第四步启动后，在管理网页的「成员角色」页里加）。

> 角色名可以改：启动前设置环境变量 `BOSS_ROLE=你的老板角色名`、`TAKER_ROLE=你的打手角色名`。

## 第四步：启动

| 系统 | 操作 |
|---|---|
| Windows | 双击项目根目录的 **`start.bat`** |
| macOS / Linux | 终端进入项目目录，运行 `./start.sh`（第一次先 `chmod +x start.sh`） |
| 任意系统 | 终端进入项目目录，运行 `node scripts/start.mjs` |

启动成功会看到：

```
✔ 派单平台已启动：http://127.0.0.1:8787　（登录密码在 admin-password.txt）
→ 管理网页：http://127.0.0.1:8787
→ 登录密码在：……/dispatch/admin-password.txt
```

并自动打开浏览器。**登录密码**是第一次启动时随机生成的，保存在 `dispatch/admin-password.txt`，用记事本打开即可；想换密码就改这个文件再重启。

- **窗口不要关**：关掉窗口 = 平台停止，机器人不再接单。按 `Ctrl+C` 也能停。
- 端口被占用时可以换端口：`PORT=9000 node scripts/start.mjs`（Windows PowerShell：`$env:PORT=9000; node scripts/start.mjs`）。
- 不想自动开浏览器：设置环境变量 `NO_BROWSER=1`。

## 管理网页使用说明

地址：<http://127.0.0.1:8787>（只有运行平台的这台电脑能打开）。

顶部显示机器人名、网关连接状态（绿点 = 已连接 KOOK）、当前识别方式，以及各状态订单数量。

### 订单

| 列 | 内容 |
|---|---|
| 订单号 | `KD + 日期 + 序号`，如 `KD20261022-001` |
| 创单 / 开始 / 结束 | 创单时间；开始时间 = 创单 + 5 分钟；结束时间 = 老板结单的时刻 |
| 状态 | 待接单 → 待选人 → 进行中 → 待结单 → 已完成（或已取消） |
| 派单人 | 老板的昵称和 `用户名#识别号` |
| 用户信息 | 游戏、要求、人数、时间 |
| 接单人 / 评分 | 被选中的打手和老板给的星级；没选人时显示报名人数 |
| 持续时长 | 结束时间 + 5 分钟 − 创单时间 |

- 顶部可按状态筛选、按订单号 / 老板 / 打手 / 游戏 / 要求搜索；每 15 秒自动刷新。
- 点「**详情**」看老板原话、识别方式、报名的所有打手、邀请链接和完整时间线。
- 「待接单」「待选人」的订单可以点「**取消**」。

### 成员角色

- 列出服务器全部成员，可按角色（上方标签，带人数）、在线状态、名字筛选。
- 角色标签上的 **×**：撤销该角色；「**+ 添加…**」下拉框：授予角色。每次都会弹窗确认，**直接修改 KOOK 服务器**。
- 带「管理员」权限的角色需要二次确认。
- 成员列表缓存 60 秒，点「从 KOOK 刷新」立即重新拉取。

### 操作日志

网页上每一次改角色、取消订单、修改识别设置都会记录（不会记录 API Key 明文）。

## 配置大模型 API（识别设置）

老板下单有两种方式：

1. **固定格式**（不需要大模型，零成本）：`派单 游戏:三角洲 要求:改枪 人数:1 时间:今晚9点 备注:会玩狙`
2. **随口说**（需要大模型）：「今晚九点来个人带我打三角洲改枪」

想支持第 2 种，在管理网页 →「**识别设置**」页填写：

| 项 | 说明 | 示例 |
|---|---|---|
| API Key | 你在大模型服务商那里申请的 Key | `sk-……` |
| 接口地址 | **OpenAI 兼容**接口的地址，必须 `https://` 开头，不要带 `/chat/completions` | `https://api.deepseek.com`（默认） |
| 模型 | 服务商提供的模型名 | `deepseek-chat`（默认） |

保存后**立即生效，不用重启**。页面上只显示 Key 的最后 4 位；Key 保存在本机 `dispatch/llm-key.txt`，接口地址和模型保存在 `dispatch/llm-settings.json`（都不会被提交到 Git）。点「清除 Key」可删除。

常见 OpenAI 兼容服务（接口地址以各服务商官方文档为准）：

| 服务商 | 接口地址（示例） | 模型（示例） |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | 你账号可用的模型名 |
| 其他兼容服务 | 服务商文档里的 Base URL | 服务商文档里的模型名 |

**识别顺序**：固定格式 → 大模型（填了 Key 时）→ 人工识别（没 Key 且开启时）→ 都不行就提示老板用固定格式。

> 隐私提示：开启大模型后，非固定格式的下单原话会发送给你配置的大模型服务商。
> 安全设计：下单原话被当作纯数据，模型只做字段提取；模型的输出也会逐项校验，**不会触发任何管理操作**。

<details>
<summary>高级：人工识别（默认关闭）</summary>

勾选「没有 Key 时，由 Claude 人工识别」后，没有 Key 时下单原话会进入 `dispatch/data/recognize/pending/` 队列，平台先私信老板「正在识别」，最多等 5 分钟。需要有人（或一个 AI 编程助手会话）值守：

- `node dispatch/watch-pending.mjs`：每出现一条待识别订单输出一行 JSON
- `node dispatch/answer.mjs <id>`，从标准输入写入结果：
  `{"is_order":true,"game":"","requirement":"","headcount":1,"play_time":"","notes":""}`

没人值守时 5 分钟后超时，提示老板改用固定格式。
</details>

## 下单格式与订单规则

### 谁能做什么

| 操作 | 谁能做 | 在哪做 |
|---|---|---|
| 下单 | 有「老板」角色的人 | 私信机器人，或在频道里 @机器人 |
| 接单 | 有「打手」角色的人（不能接自己的单） | 私信里的订单卡片 [接单] |
| 选人 | 只有下这个单的老板 | 私信里的报名卡片 [选TA] |
| 提交结单 | 只有被选中的打手 | 邀请卡片里的 [提交结单] |
| 结单评分 / 暂不结单 | 只有下这个单的老板 | 私信里的结单卡片 ★ ~ ★★★★★ / [暂不结单] |
| 取消订单 | 管理员 | 管理网页（只能取消还没派出的单） |

### 时间规则

- **开始时间** = 创单时间 + 5 分钟
- **结束时间** = 老板点星级结单的时刻
- **持续时长** = 结束时间 + 5 分钟 − 创单时间

### 其他规则

- 每单最多推送 30 位打手，每条私信间隔约 1 秒（防止触发 KOOK 限速）。
- 同一订单的按钮点击排队处理：两个打手同时接单都会被记录；老板连点不会重复派单或改分。
- 老板选人时如果不在任何语音频道：频道下单的用下单的文字频道邀请；私信下单的用整个服务器的邀请。
- 选人前请老板**先进语音频道**。

## 安全须知

- 管理网页**只监听 `127.0.0.1`**，局域网和公网都访问不到；还会校验 Host 头（防 DNS 重绑定），必须登录，修改类请求带防跨站伪造校验。
- 机器人在 KOOK 里看到的所有文字都只当数据处理，**任何聊天内容都不会触发角色修改、踢人等管理操作**；身份一律按 KOOK 角色和按钮点击者的用户 ID 判断。
- 这些文件含机密或隐私，已被 `.gitignore` 排除，**永远不要上传或分享**：

| 文件 | 内容 |
|---|---|
| `kook-token.txt` | 机器人 Token |
| `dispatch/admin-password.txt` | 管理网页密码 |
| `dispatch/llm-key.txt` | 大模型 API Key |
| `dispatch/data/`、`bot/data/` | 订单数据库、派单日志、成员快照、聊天记录 |

## 自测与排错

```bash
node bot/selftest.mjs          # 机器人底层离线自测（不联网）
node dispatch/selftest.mjs     # 派单平台离线自测（不联网、不碰真 KOOK）
node bot/probe.mjs check       # 联网检查：Token 是否可用、机器人在哪些服务器、有哪些文字频道
```

| 现象 | 可能原因 |
|---|---|
| 启动提示「没找到机器人 Token」 | 根目录没有 `kook-token.txt`，或文件是空的（记得保存） |
| 启动提示「找不到「老板」或「打手」角色」 | 服务器里没建这两个角色，或名字不一致（可用 `BOSS_ROLE` / `TAKER_ROLE` 指定） |
| 网关一直「连接失败」 | Token 错误或已重置 |
| 老板下单后机器人回复「只有「老板」角色可以派单」 | 这个人没有老板角色 |
| 打手收不到推送 | 没有打手角色；或该成员关闭了私信 |
| 网页加角色报 `40300` | 机器人角色排在目标角色下面，或没勾「管理角色权限」 |
| 邀请链接是服务器邀请而不是语音频道 | 老板选人时不在语音频道（KOOK 的频道人员查询也有几秒延迟） |

## 已知限制与待开发

- **语音转文字（STT）/ 文字转语音（TTS）：待开发。** KOOK 机器人语音接口只能往频道推流播放，**不能接收**他人语音；可行方向是在本机采集声音并本地识别，尚未实现。
- 实时网关未实现断线续传（RESUME），断线重连的几秒内的消息可能漏掉。
- 管理网页只支持本机访问、单一管理员密码，没有多账号体系。
- 平台需要一直开着窗口运行；关机或关窗即停止。

更多接口细节见 [docs/kook-api-notes.md](docs/kook-api-notes.md)。
